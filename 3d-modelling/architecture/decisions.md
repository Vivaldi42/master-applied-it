# Decisions

Chronological list of the decisions about the pipeline and the prototypes. Dates are in 2026.

| # | Date | Run | What happened | Decision | Drawback |
|---|---|---|---|---|---|
| 1 | 18-11 or earlier | Before exp001 | The methods need different environments. | Steps run separately and exchange files. Runs are never overwritten. | More files. |
| 2 | 19-11 | After exp001 | COLMAP took more than 2 h. Heijmans needs counts, not positions. | **No 3D model for now.** SAM 3 is tested alone. | Nothing links two views of the same object. |
| 3 | 19-11 | exp002 | SAM 3 tracks better when motion between frames is small. | Frames at 10 fps and 1920 px wide. | More frames cost more time and memory. |
| 4 | 19-11 | exp002 | SAM 3 gives each tracked object an ID. | **Count = number of distinct IDs.** | It over-counts when an object gets a second ID ("monitor": 4 instead of 2). |
| 5 | 19-11 | After exp004 | Several asset types in one process ran out of GPU memory (exp003, exp004). | **One process per asset type.** (In exp003 and exp004, all asset types were searched for in one process.) In exp005, 9 of 11 completed and 3 of 9 counts were correct. | The model is loaded again for every asset type. |
| 6 | 23-11 | After exp005 | Design choice: only the types in the Heijmans' asset table are needed. | **The asset list is given as input.** | Other types are not found. |
| 7 | 23-11 | After exp005 | A crashed run leaves partial data, which looks like a valid count. | A failed detection gives an empty count. | - |
| 8 | 24-11 | After exp005 | The errors have different directions and causes. | **Measure = signed count error per asset.** | Errors can cancel out, so the images must be checked. |
| 9 | 24-11 | exp006 | The steps were started by hand. | One command runs all steps (`code/run_mvp.sh`). All 3 asset types in exp006 ran out of GPU memory. | - |
| 10 | 25-11 | exp007 | SAM 3 copied all frames to the GPU (10.5 GB). | Frames stay in RAM and one frame at a time goes to the GPU. The peak for "monitor" fell from 21.1 to 10.6 GB with identical detections. | - |
| 11 | 25-11 | exp007 | The memory fix changes one SAM 3 function. | The function is replaced at runtime, so `external/sam3` stays unmodified. | A new SAM 3 version can break it. |
| 12 | 25-11 | exp008 | The fix leaves enough memory on both GPUs. | Two asset types run in parallel, one per GPU. "door" and "cardboard box" are omitted. | - |
| 13 | 25-11 | exp009 | Wrong input: `assets-to-find.csv` listed the room001 assets, so the run used the ground-truth list. | Run stopped by the architect. No results. The number is not reused. | - |
| 14 | 25-11 | exp010 | First run on room002 (10 asset types). "door" and "window" crashed because SAM 3 returned an object with an empty mask. | Objects with an empty mask get no overlay. Checked outside a run: both asset types complete ("door" 9 IDs, "window" 13 IDs). | - |
| 15 | 25-11 | After exp010 | SAM 3 found 3 power sockets, the hand count was 2. The third socket is visible in the video. | The hand count was corrected to 3. With this correction, exp010 has 4 exact counts of 8 completed. `evaluation.csv` still contains the old value. | - |
| 16 | 25-11 | exp011 | "door" only, all visible frames saved per ID. 9 IDs for 2 doors: wrong objects, second IDs and IDs that move to another object. | One asset type per experiment. The architect starts the experiments. | - |
| 17 | 25-11 | After exp011 | Detection errors and tracking errors are mixed in the count. | **Detection is improved first, on single images without tracking.** Test set: 43 images of room002, one every 2 s, marked by hand before the SAM 3 boxes are seen. | One video only. |
| 18 | 25-11 | After exp011 | It was not defined what counts as a door. | A partly visible door and a door seen through a doorway count. A doorway without a door does not count. | - |
| 19 | 25-11 | exp012 | SAM 3 on 43 single images: all 8 certain doors found, 15 wrong boxes at a score limit of 0.5 (not checked). | **Finish the prototype first:** it shows a picture of each detected object and a person removes the wrong ones. Better detection comes later. | Missed objects are not shown. |
| 20 | 25-11 | exp011 | SAM 3 found 9 doors. The architect checked one picture per object: 2 correct, 2 duplicate, 5 wrong. The final count is 2, equal to the hand count. | **The final list contains only objects that a person marked as correct** (`review.py`, `finalize.py`). | Objects that SAM 3 missed cannot be added. The time needed for the check is not measured yet. |
| 21 | 26-11 | After exp012 | The documents mixed the general pipeline with the SAM 3 prototype. | One document for the pipeline (`pipeline-design.md`) and one per prototype (`prototype-1-sam3.md`). A second prototype, for example with another detector, gets its own document. | - |
| 22 | 26-11 | After exp012 | A check by a person would measure the person, not the method. | **The person's check is not part of the prototype.** The prototype output (`counts.csv`) is compared with the ground truth without corrections. The review pictures and verdicts remain analysis tools. Replaces decision 20. | - |
| 23 | 26-11 | After exp012 | The goal is to compare methods, not to deliver a product. | **Three levels: research question, evaluation pipeline and methods.** The evaluation is part of the pipeline. SAM 3 is method 1. Documents: `pipeline-design.md` and `method-1-sam3.md`. Replaces decisions 21 and 22. | - |
| 24 | 26-11 | After exp012 | Ten code files in six folders were hard to follow. | **One entry program `code/run_pipeline.py <method> <room>`.** Each method is one file in `code/methods/` and runs as a separate program in its own environment. Fixed file names per room folder. The analysis tools (review pictures, single-image test) were removed. Earlier versions are in `backup-26-11-2026`. Run folders no longer contain "none" in the name. | - |
| 25 | 26-11 | Before the verification runs | room001 has many small cardboard boxes, so no reliable hand count exists. Heijmans does not need boxes. | "cardboard box" removed from room001. "door" added to the asset types, because it no longer runs out of GPU memory. | - |
| 26 | 26-11 | Before the verification runs | room001 has 1 wall socket and 5 outlets on a movable power strip. Two of the 3 plants are hardly visible in the video. | **Power socket = fixed wall socket only**, because Heijmans maintains building assets. room001: 1 instead of 6. "potted plant" removed from room001. | - |
| 27 | 26-11 | After decision 26 | The asset name is also the SAM 3 text prompt. "power socket" may include outlets on power strips. | "power socket" renamed to "wall socket" in both rooms. Counts of this asset type are not comparable with runs before 26-11. | - |
| 28 | 28-11 | After the error analysis of exp016 and exp017 | Doors and windows have many variations. Most extra IDs are objects of the right type that are not assets of the room. The problem analysis names the fire extinguisher as a key asset. | **The next experiments focus on one asset type: fire extinguisher.** It has fewer variations and distinctive features. | The test data contains only one fire extinguisher, so new videos are needed (except for room001 and room002). The results do not show whether the method works for other asset types. |

Bold: decisions that have the largest effect on the results.
